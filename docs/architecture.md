# 架构草案

> 【草案】本页只固定方向，不是可直接实施的详细设计。定稿前不得据此编写插件加载、消息总线或 UI 组合实现。

## 已确定方向

总体采用微内核插件化：WPF 宿主负责 shell 与组合，`TongYiTong.Core` 承载契约、消息和串口抽象，终端、CRC 工具及后续协议解析作为插件。技术栈与依赖选型以 [ADR-0001](decisions/0001-wpf-net10-stack.md) 为准。

当前只有项目边界和模板，没有架构实现。

## 待决问题

- Core 契约的类型、职责边界与公开 API 形状。
- 插件发现、加载、激活、隔离和失败处理模型。
- 宿主与插件、插件与插件之间的消息机制。
- 插件 UI 的组合、导航、生命周期和资源管理方式。
- 契约与插件的版本兼容、发布和升级策略。
- 串口生命周期与多会话模型如何映射到上述契约。

## 定稿流程

1. 领取并完成 [plans/0002-architecture-design.md](plans/0002-architecture-design.md)，逐项比较备选方案。
2. 用定稿内容替换本页草案，明确边界、流程和约束。
3. 对新增或改变的决策分别补充 ADR；只记录真实决策，不倒填结论。
4. 将定稿设计拆成独立实现票，再按 [workflow.md](workflow.md) 实施和验收。
