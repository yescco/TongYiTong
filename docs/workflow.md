# 开发工作流

1. 从 `docs/plans/` 领取任务票，确认范围、依赖与验收清单；没有任务票先补任务票。
2. 阅读根目录 `AGENTS.md`、相关专题文档和 ADR，不实现未批准或尚未定稿的设计。
3. 小步实现并同步更新受影响的文档与测试；不夹带无关重构。
4. 在仓库根目录运行 `dotnet run scripts/check.cs`，脚本依次执行格式验证、构建和三个代码测试层。
5. 检查失败必须修复后重跑，不能通过忽略规则掩盖问题；手动验收按任务票单独记录。
6. 核对差异和生成物，完成任务票验收记录后提交。提交信息使用简洁的约定式提交格式。

```sh
dotnet run scripts/check.cs
git status --short
```

pwsh 只作为调用 shell，不承载自动化逻辑；新增可重复执行的仓库自动化应使用 C# file-based app。
